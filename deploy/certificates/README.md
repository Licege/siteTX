# Автоматическое продление сертификатов

Certbot в `docker-compose.yml` проверяет сертификаты каждые 12 часов. Политика
`restart: always` запускает его после перезагрузки сервера и при падении контейнера.
Каталоги `data/certbot/conf` и `data/certbot/www` должны сохраняться между деплоями.
Для проверки доменов должен быть доступен порт 80, а DNS должен указывать на сервер.

Nginx подхватывает новые сертификаты через системный таймер Linux с systemd.
После запуска production-контейнеров один раз выполните из корня проекта:

```sh
sudo sh deploy/certificates/install.sh
```

Эту же команду выполняйте при изменении файлов таймера или скрипта. Установщик
также применяет политику автозапуска к уже работающему Certbot без перезапуска.
При обычных деплоях переустанавливать таймер не требуется.

Раз в минуту таймер сравнивает содержимое сертификатов, ключей и цепочек.
При изменении он проверяет `nginx -t` и выполняет `nginx -s reload`.
При ошибке повторяет попытку на следующем запуске. Контейнер Nginx продолжает
работать. Путь к сертификатам определяется по его Docker mount, имя контейнера — `nginx`.
На новом сервере настройку таймера нужно установить отдельно; одного `docker compose up` недостаточно.

Проверка продления (тестовый центр сертификации, рабочие сертификаты не заменяются):

```sh
docker exec service_certbot certbot renew --dry-run --no-random-sleep-on-renew
```

Проверка таймера и журналов:

```sh
systemctl list-timers sitetx-certificates.timer
journalctl -u sitetx-certificates.service -n 30 --no-pager
docker logs --tail 100 service_certbot
```

DNS-ошибки в `renew --dry-run` нужно исправлять у DNS-провайдера. Таймер применения
не может компенсировать ошибку выпуска сертификата.
